# Документный движок

Один механизм на все порождаемые документы: договоры, законопроекты, дальше —
процессуальные бумаги. До него каждый модуль решал одну и ту же задачу
по-своему, и трижды написанное расходилось в мелочах, из которых и
складывается качество юридического документа.

## Как это устроено

Документ хранится **деревом**, а не строкой разметки:

```
DocTree
  meta         вид, тип, язык, заголовок, правовая основа
  requisites   номер, город, дата, стороны с реквизитами
  preamble     вводная формула
  sections[]   разделы → clauses[] пункты → subclauses[] подпункты
  tables[]     спецификации, графики, сравнительные таблицы
  annexes[]    приложения
  issues[]     замечания проверки
```

Из этого следует всё остальное:

- **пункт адресуем** — «перепиши 4.2» становится операцией над узлом, а не
  поиском подстроки;
- **состав проверяем** — движок знает, каких существенных условий не хватает;
- **один источник на все форматы** — лист на экране, DOCX, PDF и XLSX
  собираются из одного дерева, поэтому «как на экране, так и в файле».

## Правка промптом

Модель не переписывает документ целиком, а возвращает **список операций**:

```json
{"ops": [
  {"op": "replace_clause", "no": "4.2", "text": "…"},
  {"op": "insert_clause", "key": "liability", "text": "Пеня 0,1% за день просрочки."}
]}
```

Так модель не может незаметно потерять половину договора. Операция, не нашедшая
цель, возвращается пользователю **отказом**: молча проглоченная правка хуже
видимой ошибки, потому что человек уверен, что договор изменён.

Пункт, правленный человеком, помечается `locked` и переживает перегенерацию
раздела.

## Как добавить тип договора

Паспорт типа — это **данные**, а не код. Юрист правит их без программиста.

1. Создайте `docengine/catalog/contracts/<id>.yaml`.
2. Опишите: правовую основу, роли сторон, поля формы, разделы с `guidance`,
   существенные условия, риски, приложения.
3. Проверьте загрузку:

```bash
python -c "from docengine.passport import load_catalog; print(sorted(load_catalog()))"
```

Ошибка в одном файле роняет загрузку каталога целиком — это намеренно:
пропущенный битый файл означал бы, что тип договора молча исчез из каталога.

Ключевое поле — **`guidance`** у раздела. Это прямая инструкция модели, что
раскрыть, и качество генерации зависит от него больше, чем от чего-либо ещё.
«Опиши предмет» даёт воду; «укажи наименование, количество, качество товара и
сошлись на ст. 407 ГК РК» даёт документ.

**`essential_terms`** — существенные условия по ст. 393 ГК РК: без них договор
считается незаключённым. Движок проверяет их наличие в готовом документе.

**`reviewed: false`** значит, что паспорт не вычитан практикующим юристом.
Интерфейс говорит об этом пользователю прямо. Снимать флаг вправе только
юрист, проверивший ссылки на нормы.

## Генерация

Разделы пишутся **по очереди**, каждый видит предыдущие: иначе модель заново
вводит уже определённые термины и путает внутренние ссылки. Правовой контекст
ищется **под каждый раздел отдельно** — нормы про предмет поставки и нормы про
неустойку разные, и один общий запрос на весь договор всегда находил среднее,
то есть ничего.

Упавший раздел не роняет документ: он помечается замечанием и остаётся пустым.
Потерять девять готовых разделов из-за десятого хуже, чем отдать документ с
одной дырой, про которую честно сказано.

Работа идёт в **фоновой задаче**: генерация занимает минуты, а внутри
HTTP-запроса такое не живёт — прокси рвёт соединение, и результат пропадает,
хотя модель его уже сделала.

## Очередь

Таблица `jobs` в PostgreSQL, разбор через `FOR UPDATE SKIP LOCKED`. Ни Redis,
ни Celery: это две дополнительные системы ради очереди, которая укладывается в
одну таблицу.

```bash
python scripts/worker.py          # воркер отдельным процессом (производство)
DOCENGINE_INLINE_WORKER=1 …       # воркер в потоке приложения (разработка)
```

Задача, чей воркер молчит дольше десяти минут, считается брошенной и
возвращается в очередь.

## Проверка

```bash
pytest tests/                          # движок, операции, рендер, API
python scripts/smoke_generate.py       # живая генерация настоящей моделью
```

Живая проверка расходует квоту провайдера, поэтому в тесты не входит. Но
только она отвечает на главный вопрос: получается ли документ, который юрист
согласится открыть.

## Известные ограничения

- **Ссылки на нормы не выверены.** Модель охотно выдумывает номера статей.
  `Ref.verified` остаётся `false`, интерфейс помечает такие ссылки. Сверка с
  корпусом — отдельный шаг, которого пока нет.
- **Обрыв ответа по лимиту токенов** выглядит как «модель не поняла схему».
  Базовый интерфейс провайдера не возвращает причину остановки, поэтому
  отличить одно от другого сейчас нельзя.
- **Паспорта не вычитаны юристом.** Ссылки на статьи перенесены из прежнего
  кода, где их тоже никто не проверял.
